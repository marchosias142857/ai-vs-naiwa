# 新青蛙原画与当前 v4 导出

#100 保留负责人选定的新青蛙设计与少帧动作。v3 合并后，负责人要求适度提高精度；当前 v4 从同一批源图重新采样，每边像素密度提高 50%，不增加动作帧。`design.png` 是本轮从零生成的概念总览；`sources/` 是根据该新设计绘制的 16 张动作图与奶怪补充图。没有把旧 v1/v2 贴图或原始奶怪图当重绘参考。来源为本轮内置 ImageGen，提示词见 `prompts.json`，当前文件摘要见 `source-hashes-v4.json`；不引入第三方素材包。

## 重建

使用 Python 3、Pillow、numpy（与现有美术工具环境一致，无新增 npm 依赖）：

```sh
python art-src/monsters-v3/build.py --preview /tmp/frog-preview
npx prettier --write src/data/monsterArt.ts src/data/naiguaiArt.ts art-src/monsters-v3/build-report-v4.json
npm run check
```

输出为两张 `public/assets/demo/*-v4.png`、两个 TypeScript 注册表和 `build-report-v4.json`。普通怪与 Boss 分别使用一张纹理，纹理 key 和怪物 ID 不变。可选 `--partial` 只预览已经存在的原画，绝不发布残缺注册表。

## 像素与动作

每张源图固定四列六行：待机 4、移动 4、蓄力 2 + 攻击 2、收招 2 + 受击 2、特殊 4、死亡 4；普通怪合计 24 帧。奶怪额外补旋身 4、大笑 4，共 32 帧。普通种类的特殊行可作为表情备用，跳蛙、钻地蛙、舞蛙与奶怪则对应已有 air/buried/spin 状态；不为所有备用动作新增 sim 行为。

导入器按透明行间隔和完整连通区域拆图，防止伸出的四肢被列边界切断；随后统一身体锚点、最近邻降采样、限制单种配色、固定全套帧的尺寸与留白。普通怪常态主体约 27–54 原生像素，奶怪约 90；运行时 scale 为 1/3，抵消像素密度提高以保留游戏中的体型，不降低游戏画布分辨率。每帧来自独立绘制的姿态，不通过平移静态图补帧。

`manifest.json` 的 fit 保留 v3 基准尺寸，导出时统一乘以 `PIXEL_DENSITY=1.5`；身体锚点比例与特殊行用途不变。普通怪色板预算由 14 提高到 18，奶怪由 20 提高到 30；巨爪蛙保留强调眼睛对比的固定色板。源图透明 alpha 在导入时变成 0/255；透明像素 RGB 清零。最终 PNG 使用精确索引编码，并断言解码 RGBA 与编码前完全相同。每种怪物所有动作共享 pivot、脚底线和帧尺寸，左右翻面不会移动物理圆。

动作时长由 `seconds` 驱动。待机循环 0.96 秒、移动循环 0.36 秒；蓄力/攻击/收招取已有 sim 状态时长，播到末帧保持。受击只覆盖普通待机、移动或收招，0.16 秒后回到原动作时钟，不遮住危险出招。普通死亡保留 0.45 秒，奶怪保留 3 秒。

验证、资源成本和当前限制见 [v4 验证记录](../../docs/testing/monster-art-v4.md)。旧生成器保留作历史来源，不再生成当前运行资源。

`build-report.json` 和 `source-hashes.json` 保留 v3 历史数据；原画及提示词未变。当前导出使用带 `-v4` 后缀的报告和摘要。
