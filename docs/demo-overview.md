# AI 大战奶蛙：demo 架构与评审入口

> 开发中。目标是完整可玩的一局，视觉仍为灰盒；不是另一个《奶蛙大战 AI》项目。

## 集成方式

`gpt/demo` 从已合并 #30 的 main 创建。每个功能独立 PR，验证后 squash 到集成分支；Claude 最后按下列顺序集中评审，负责人决定合入 main。

## 实现顺序

1. demo 分工与评审入口（本文、AGENTS.md）。
2. 地牢数据/schema 与确定性生成：5×5 网格、主路径与支线、全图连通。
3. 纯 sim 房间/楼层状态：锁门、有限波次、清房、探索、出口、胜负统计。
4. 武器弹道与装备：多把武器、切换、能量、数据驱动。
5. 敌人行为与攻击：追击、远程、炮台、冲锋及 Boss 阶段。
6. 玩家资源与掉落：护甲、技能、拾取、宝箱、奖励选择。
7. Arcade 房间适配：墙体、门、视线、切房与池复用。
8. 场景接线：开局、地图、HUD、交互、死亡/胜利、结算与重玩。
9. 反馈与服务：预热特效、音频开关、设置、进度与续玩。
10. 完整流程、不同物理步长、对象池与离线回归；补截图和最终评审索引。

## 不变的边界

- sim 只依赖 data；Phaser 只负责物理结果与表现；同种子由子系统 fork 保持可复现。
- WORLD_STEP：寿命 → 同步物理位置 → sim.step → 清边沿 → 应用速度 → 消费子弹，再推进房间流程。
- 数据含 schema；共享契约变更附 ADR；临时灰盒布局不构成正式画面方案。
- 子弹、命中特效与掉落表现使用固定池；场景结束后清理全部监听。
