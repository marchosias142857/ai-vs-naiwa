# 0020. 取消玩家自动瞄准，不瞄准时朝面向开火

> 更新：攻击轮盘死区/首发等待和弹体选敌规则由 [ADR 0043](0043-projectile-auto-aim.md) 替代；下文保留当时决策，其他输入所有权、布局与身体表现规则继续适用。

- 状态：提议
- 提出者：Claude
- 批准：负责人（合并即批准）
- 关联：Issue #64；修订 ADR 0002 中 `InputFrame.aim` 为 `null` 的含义

## 背景

负责人决定（2026-10-24）：

- 手机的开火键改成开火轮盘：按住不拖，朝角色面向的方向开火；拖动，就朝拖的方向开火。
- 玩家不再有自动瞄准；自动瞄准以后作为特殊武器的能力再加。

ADR 0002 约定 `aim: null` 表示「交给自动瞄准」，触屏默认如此，手柄右摇杆不推时也是。这条约定与新决定冲突。

## 决定

- `InputFrame.aim` 为 `null` 的含义，改为「此刻没在瞄准」（轮盘或右摇杆在死区内）。字段和类型都不变，只改语义。
- 玩家朝向的规则（每个物理步都在 `CombatWorld.step` 里计算）：
  - 正在瞄准（`aim` 非空）：朝向 = 瞄准方向；
  - 没在瞄准、但在移动：朝向 = 移动方向；
  - 都没有：保持上一次的朝向。
- 开火始终沿当前朝向。冲刺在不移动时也沿当前朝向，这一点不变。
- 规则对所有输入设备一样：
  - 触屏：开火轮盘，见 Issue #64 的视觉方案；
  - 手柄：右摇杆不推时按 RT，朝面向开火；
  - 键鼠：鼠标在画面内时一直在瞄准，行为不变。
- `AutoAim` 模块和 `BALANCE.autoAimRetargetInterval` 保留，留给以后带自动瞄准能力的特殊武器；那时由武器数据声明这项能力，另开 ADR。
- 敌人开火不受影响：敌人一直按 ADR 0009 瞄准玩家，并按 #57 从身体中心对准碰撞圆心。

## 影响

- sim（Claude，本 ADR 的 PR）：
  - CombatWorld 不再创建和使用 AutoAim；
  - 更新 `types.ts`、`api.ts` 中关于自动瞄准的注释；
  - 更新依赖自动瞄准的单测和浏览器测试，改为显式瞄准或朝面向开火。
- game（GPT，Issue #64）：
  - 触屏开火轮盘、瞄准提示线；
  - 菜单操作说明（`menu.controls`）里「右按钮自动射击」的文字；
  - 测试里不推右摇杆按 RT 的用例，现在朝面向开火。
- 存档 v2（ADR 0019）：玩家不再有自动瞄准状态，0019 第 1 节列出的「自动瞄准的当前目标与下次换目标的时间」不再需要保存。玩家朝向本来就在实体记录里。
- 手感会明显变化：手机上必须自己瞄准，打快速移动的怪会更难。数值是否要随之调整（例如敌人速度、子弹散布），由负责人试玩后决定。
- 回退方式：在 CombatWorld 里恢复 AutoAim 的调用即可，接口没有变。

## 备选方案

- **保留自动瞄准作为默认，轮盘只用来手动瞄准**：负责人否决。自动瞄准应当是特殊武器的能力。
- **按住不拖时朝最后一次的移动方向开火**：站着往左瞄完、松手再按，子弹会突然朝另一个方向飞，违反直觉。所以改为保持上一次的朝向。
- **只改触屏，手柄保留自动瞄准**：不同设备手感不一致，以后加特殊武器时也更难定义。
