# ADR 0037：怪物图集 v2 与固定身体锚点

- 状态：待负责人画面验收与合并批准。
- 提出者：GPT，负责人指定独立完成 #100。
- 延续：ADR 0023、0030、0033、0036。

## 问题

普通怪图集生成器用 `帧高 - 2 - radius / scale` 推算 pivot，把尾巴、长腿、帽子和透明边距都隐含进身体位置。腿蛙的 pivot 落在腿部，蝌蚪的尾巴和喇叭蛙的喇叭影响水平居中。奶怪按每帧包围盒中心及脚底对齐，伸拳、弯腰会改变主体与锚点的关系。

## 决定

1. `ActorView.x/y` 继续表示**身体圆心**，与 sim、Arcade、导航、接触和攻击判定一致。修正 API 中遗留的“脚底中心”注释，类型和运行行为不变。
2. 普通怪生成器显式记录每种怪物的原生身体 pivot，再加透明边距；不再复制或读取碰撞半径。奶怪继续使用负责人原始 12 帧，以奶白色肚皮的中心对齐，再计算统一帧尺寸与透明留白。取样失败直接报错。
3. 所有图集像素仍为 0.5 世界单位，硬边 alpha 为 0/255。普通怪朝右、奶怪原图朝左；`EnemyArt` 使用现有镜像 pivot、像素对齐与 `lift`，物理代理不读取图集尺寸、图片缩放、帧号或动作。新增可选 `MonsterArt.shadowY`（图集内固定脚底线）只用于影子：长腿和奶怪的脚底不再由碰撞半径推算，腾空时影子留地；旧资源省略时仍用 radius。
4. 逐种审计后保留 `ENEMIES.radius`：3、4、5、6、8、9、14 共 7 种；玩家半径没有增加第 8 种，`NAVIGATION.radiusCaches=8` 足够。没有攻击、速度、生命、半径、寻路规则或物理 offset 的数值改动。大小怪复用继续由 `CombatActors.acquire/load` 完整设置圆、offset、前帧位置与 enable。
5. 资源 URL 升为 `monsters-v2.png` / `naiguai-v2.png`，纹理 key 和怪物 ID 保持稳定。帧注册和图鉴继续共用 `enemyAnimation()`。退休运行目录中的 v1 PNG，Workbox 从当前构建生成预缓存；旧页面依旧使用自身已激活版本，用户确认更新后才换整套资源。
6. 待机、行走补画中间参数后重新栅格化，帧时间同步减半，循环总时长不变。完全相同的像素帧共享同一图块，帧名和动作时序完整保留。死亡、特殊招式原时长不变。街舞旋转由 4 帧补为 8 帧，同样保持循环时长。
7. 存档格式、物理数据指纹不变；生产代码包内容哈希随注册数据更新，跨构建存档仍走现有入口兜底，同构建完整恢复不受影响。不新增存储键，不改 FxBudget，不移除危险提示。

## 验证与取舍

新增真实 Arcade 测试覆盖 16 种怪物的所有动作和缺帧替补、左右镜像、腾空显示、圆周探针、墙面/世界角落/圆桶、读档形状恢复、死亡停用，以及 Boss→蝌蚪等 34 次槽位获取。图片测试实际解码 PNG，检查全部 390 个注册帧的非空内容、透明边界与硬像素 alpha。

圆形判定是可碰撞主体的近似，不追踪长腿、眼球、尾巴、喇叭、烟雾或每帧变形。完整清单、图例、资源成本、回归与 #101 动作缺口见 [#100 验证记录](../testing/monster-art-v2.md)。最终画面与手机手感由负责人验收，自动化不代替真机结论。
