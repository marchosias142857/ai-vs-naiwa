# ADR 0024：逻辑坐标与高分辨率渲染分离

状态：待负责人合并批准。

## 背景

负责人要求贴图本身是像素画，而整张画面不能先渲染成低分辨率再放大。旧版将高分辨率 PNG 压到 480×270 画布，角色仅约 18 像素高，武器和地砖细节丢失。

## 决定

- 保持 480×270 逻辑坐标、物理尺度、存档和命中规则；新增引擎常量 RENDER_SCALE = 4。
- 画布为 1920×1080。所有场景使用左上角原点、4 倍相机，把源图直接绘制到最终画布。
- 禁用整屏 pixelated 放大与逻辑坐标取整；文字独立使用 4 倍纹理分辨率。
- HUD 和触控热区仍使用 CSS 像素。鼠标通过相机逆变换获得世界坐标。
- 主角视觉比例缩小 10%，独立武器保持可读尺寸；碰撞体不随美术比例改变。
- 不新增依赖，不改变时间步长、玩法数值、存档版本或随机状态。

## 验证与限制

覆盖画布尺寸、菜单进入战斗、存档恢复、鼠标四向瞄准和移动端实际出弹；增加 WebKit 手机视口回归。模拟手机不等于真机性能验收，1080p 填充率仍需负责人在真机上确认。

## 负责人后续美术要求（2026-10-24）

- 以负责人最终提供的两张《元气骑士》角色图作为像素密度参考，保留大肥鱼身份，改为约 24–32 原生像素高的粗颗粒可爱造型。待机 6 帧由尾巴上下摆动，行走 8 帧交替迈步；身体不画手，手只在武器贴图上表现为单色长方形。
- 受击 2 帧和死亡 4 帧读取负责人选定的旧图集，不再重绘。新旧动作使用独立纹理与裁切元数据；`CharacterArtSchema.reactionScale` 校准旧图的显示比例，不改变物理体或存档。
- 每次起步或停步重置对应视觉动作的起始时间，计时来自 `sim.time`，暂停冻结；不修改 sim 的锁步和随机状态。
- 对角色、敌人、武器和环境图集单独使用 NEAREST 采样以保留像素边缘；画布、CSS 和高分辨率文字不套用全屏像素化。
- 新增开放/锁闭门框 PNG，并复用四个预建显示对象；门口判定范围、导航和锁门逻辑保持原契约。

## 后续可玩角色扩展

负责人明确之后有多个可操作角色。新增 `CHARACTER_ART` 注册表，以 `CharacterId` 为键；编译期要求每个玩法角色都有外观配置。`CharacterArtSchema` 增加图集 key、源文件、独立反应图集和逐帧数据，动作名称不再由大肥鱼的帧名决定。加载器遍历注册表，渲染器从 actor.kind 取配置，动画时钟、尺度和握持点随角色读取；固定枪口也读取对应角色的 standardGrip，仍不读取动画时钟；单测用不同帧名、时长和持握点的第二角色配置验证独立性。当前仍只有大肥鱼可选，未来选人界面及角色内容另行实现。
