# ADR 0038：怪物招式进度、方向锁定与落点视图

- 状态：提议中
- 提出者：Claude
- 批准：负责人（合并即批准）
- 关联：#101、ADR 0019（存档）、ADR 0030（怪物招式）、ADR 0031（冰冻）、ADR 0033（装饰预算）、ADR 0037（身体锚点）
- 设计：[怪物技能动画方案](../design/monster-skill-moves.md)

## 背景

#101 要求用各招式专属的动画替代怪物施放技能时的红色预警圈，并且画面由 sim 状态和招式进度驱动。GPT 的接入审计（PR #112 的 `docs/design/monster-skill-animation.md`）列出了现有视图的缺口：

1. `ActorView` 只有 `pose`、`move`、`aim`、`lift`，没有招式阶段和进度。`EnemyArt` 只能在第一次观察到动作变化时自己起一个时钟：读档首帧对不上 sim 的真实进度；渲染跳过期间同名动作重新开始了，它也分辨不出来。
2. 旧的 `charge_dash` 只写 `brain.time`，不写 `brain.span`，无法统一用剩余时间换算进度。
3. 常规射击的前摇只是冷却末段的表现，用的是 `cooldown` 和 `shot`，不走招式阶段。
4. 跳跃只给出高度和方向，没有落点。
5. 舌击、冲撞的方向锁定只写在 AI 内部的常量里，表现层看不到。

## 决定

### 1. `ActorView` 新增六个只读字段（共享契约）

| 字段             | 类型         | 含义                                                                                                                        |
| ---------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `stage`          | `ActorStage` | 招式阶段，取值与 AI 内部阶段相同：`ready`、`windup`、`dash`、`recover`、`air`、`active`、`buried`、`emerge`、`spin`、`stun` |
| `stageTime`      | `number`     | 本阶段已过的秒数，范围 0～`stageSpan`                                                                                       |
| `stageSpan`      | `number`     | 本阶段总秒数，`ready` 时为 0                                                                                                |
| `aimLocked`      | `boolean`    | `aim` 已锁定，之后到本招结束都不再改变                                                                                      |
| `landX`、`landY` | `number`     | 跳跃的预计落点，只在 `move === 'hop' && stage === 'air'` 时有效，其余为 0                                                   |

`ActorStage` 定义在 `sim/combat/api.ts`；`BrainStage` 改为它的别名，两者不会分叉。

### 2. 只从已存档的状态推导，不新增存档字段

由 `EnemyAi.stageView(actor, bounds)` 计算这几个字段，输入只有已存档的 `brain`、`pose`、`move`、位置和半径；它只写这几个视图字段，不改任何规则状态。调用点有两个：

- `CombatWorld.step` 的末尾，对全部怪物调用一次，冻住、出场预警和死亡中的也包括在内；
- `CombatWorld.load` 在恢复全部实体之后调用一次。

两个调用点用的是同一个纯函数，所以读档首帧的视图与存档前最后一步完全相同，存档格式和版本都不变。

### 3. 各类招式的推导规则

- **有招式的阶段**（`move !== 'none'`）：`stageSpan = max(span, time)`，`stageTime = stageSpan - time`，结果夹在 0～`stageSpan`。
- **常规射击**（`move === 'none'`）：
  - `pose === 'windup'` 时，`stage = 'windup'`，`stageSpan = SHOT_TELL`（0.35 秒），`stageTime = SHOT_TELL - cooldown`；
  - `pose === 'attack'` 时，`stage = 'active'`，`stageSpan = SHOT_POSE`（0.25 秒），`stageTime = SHOT_POSE - shot`；
  - 其余情况为 `ready`。
- **冲锋**（`charge_dash`）：`brain.ts` 在三个阶段切换时同时写 `span`。冲锋判定从来不读 `span`，所以规则结果不变。旧存档里 `span` 为 0，读档后按剩余时间起算，最多影响这一次动作的起始帧。
- **方向锁定**：
  - 冲锋（`dash`）：只要不是 `ready` 就算锁定，方向在前摇开始时就定了；
  - 舌击、冲撞：前摇剩余时间 ≤ `AIM_LOCK`（0.25 秒）起锁定，之后的阶段一直锁定；
  - 跳跃：起跳（`air`）起锁定；
  - 其他招式为 `false`。
- **跳跃落点**：
  - 计算：`当前位置 + 方向 × 速度 × 剩余滞空时间`，再按房间边界内缩半径夹住；
  - 每步按当前位置重算：路上无遮挡时与真实落点相差不超过一个物理步的位移，被墙挡住或被击退时逐步收敛到实际落点；
  - 不需要渲染层用速度外推。

### 4. 不改变玩法

- 不改变任何时长、冷却、伤害、阶段顺序和随机消耗，也不为了让动画播完而延后生效。
- 常规射击维持现状：冷却已到时，一进入射程且看得见就立即开火，不保证有完整前摇。要求每次射击都有完整前摇属于 AI 与手感改动，需负责人另行决定。
- 石块雨在前摇结束时生成石块并立即收招，不增加专用的收招阶段。石块本身的预警用已有的 `RockView.time / fall`。

### 5. 表现层约定（GPT 接线时遵守）

- **选帧**：
  - 进度 `p = stageSpan > 0 ? stageTime / stageSpan : 0`；
  - 前摇、出招、收招这类只播一遍的动作，第 `min(n - 1, floor(p × n))` 帧；
  - 旋转、地下这类循环动作，按 `floor(stageTime / 帧秒数) % n` 取帧；
  - 不再用表现层自己起的时钟决定这些阶段的帧。待机和走路的循环不影响判定，可以继续用表现层时钟。
- **冻住**（ADR 0031）：冻住期间不调用 AI，`stage`、`stageTime`、`aimLocked`、`landX/landY` 都保持不变，画面停在当前帧。方向、落点、范围这类提示保持显示，只停止脉动，因为解冻后招式会按剩余时间继续生效。
- **死亡、换房与槽位复用**：
  - 怪物死亡后不再画技能提示；
  - 换房时实体被移除、石块被清掉（`clearHazards`）；
  - 槽位复用时用 `id` 区分实体，视图字段来自 sim，表现层不需要缓存招式状态。
- **一次性装饰**（扬尘、碎屑等）：可以由 `enemy:acted` 触发并接入 FxBudget。必要的攻击提示（身体动作、方向、落点、范围、石块影子）只能从视图字段和 `RockView` 推出，不进装饰预算，读档首帧就能完整恢复。
- **伤害结算**：仍然只在 WORLD_STEP 里进行，渲染帧和动画回调不能触发或推迟任何判定。

## 后果

- 表现层可以删掉为技能动作自建的 `PoseClock`，同一份 sim 状态在任意渲染间隔、暂停恢复和读档后都选出同一帧。
- `ActorView` 的所有实现方都需要提供这六个字段：`CombatWorld` 的实体记录，以及测试替身（`tests/fixtures/combat.ts` 等）。
- 每步多一次遍历全部怪物（上限 31 个实体），只做数值写入，没有分配。

## 备选方案

- **把进度字段写进存档**：会增加存档字段和校验，而这些字段都能从已有状态推出，存两份反而可能不一致。不采用。
- **表现层继续自建时钟，读档时用 `enemy:acted` 补偿**：事件不会在读档时重放，暂停和跳帧也会漂移。不采用。
- **给常规射击和石块雨补上 sim 阶段，保证有完整前摇或收招**：会改变攻击间隔和手感，超出 #101「保持玩法数值」的范围。需要时由负责人另开任务。

## 验证

`tests/unit/sim/moveTiming.test.ts`，按固定物理步 1/60 秒逐步检查：

- **奶怪以外的 15 种怪物与奶怪三个阶段**：每一步都满足以下各项。
  - 进度始终在 [0, span] 内，同一阶段内每步正好加 dt；
  - 锁定后方向不再变化；
  - 起跳、落地、扑咬、冲撞、出舌、召唤、自爆、石块雨这些效果，只在前摇（或腾空）播满之后的第一步发生，常规射击开火那一步进入后坐的第 0 秒；
  - 每隔 37 步存档 → JSON → 读档，读档首帧的招式视图与存档前逐字段相同。
- **跳跃落点**：开阔场地和中间有障碍两种情况下，最后一次预计落点与真实落点相差不超过一步位移。
- **舌击锁定**：恰好在前摇剩余 0.25 秒时锁定。
- **冻结**：冻住期间阶段与进度不变、不出招；解冻后按剩余步数出舌。
- **旧存档**：冲锋的 `span` 为 0 时，读档后进度不为负。
