# ADR 0042：按风格编排房间目录、独立楼层策略与完整墙块几何

状态：负责人授权在 #115 一次完成设计、实现和验证，待 Claude 交叉复审及负责人合并。前置 #139 已合并，#114 已按负责人要求收尾。

## 目标与替换范围

不再由楼层序号查冻结目录，也不把旧布局换 ID 当新内容。`designed_v3` 提供四种风格各128个普通战斗模板，另列起点、武器、终点、Boss；四种风格的特殊房也独立布置。大厅只保留实际使用的石殿版本。前三个功能房分别为128、144、128单位正方形，保持各自固定布置；这些数值是模板尺寸，完整南墙投影会占用9.6单位地面。Boss为288方形，各风格分别放置四根24×24完整方柱，保留 ADR 0039 规则4的撞柱眩晕反制；外轮廓不晕，AI时序/数值不改。终局仍沿用安全起点→Boss的流程，不凭本任务新增终局后的下一层。大厅单列，不计入地牢候选数量。

旧 `legacy_v1` 字节基准保留为独立历史对照，但旧ID与`modular_v2` ID都不再被当前查询识别，亦不作为失败回退。已认可的地板、v19墙体和v4资源字节不改。

## 拓扑数量与风格分配

`generateDungeon(rng, boss, config)`接受明确配置；主路、支路、网格容量及特殊房名额一起校验。普通层当前默认仍是6主路+2支路；改数量只改配置。候选不够、网格没有合法位置或有限搜索预算耗尽均明确报错，不能静默少生成或回填重复房。运行、地图UI和保存数组以实际节点数为准。配置进入存档数据摘要。

`floorStyle`只负责风格分配，默认顺序独立放在数据策略中，另支持从指定风格集合带种子随机选取。房间目录/解析/编译/渲染只接受显式风格ID；相同风格可出现在任意楼层。新增风格需登记其完整美术与风格参数，而无需增加楼层编号分支。怪物波次和难度进度不是地图风格，本任务不改 AI、武器或敌人强度规则。

`selectRoomLayouts`用新建Random的`layouts:style:floor`子流打乱该风格普通候选，按节点顺序无放回选择；特殊用途查各自固定模板。重进、同构建恢复由相同种子、策略和目录重建相同清单。策略、目录和尺寸均进入dataHash；更新仍终止旧冒险并保全局外档案，不新增跨版本旧局迁移链。

## 有限的布局编排

`scripts/generate-room-catalog.mjs`在开发/构建前运行，输出只读JSON。运行时读取已验证结果，不进行随机放置搜索。

八类外壳家族各四种轮廓，共32种。所有普通房统一368×272外包围，不再用加宽计数；轮廓先按平移、旋转/镜像和宽高归一化去重。四风格都可使用这32种外壳，但**内部互不复制**。石殿使用祭坛/回廊/分区掩体，沉船使用隔舱/船脊/货舱，深渊使用礁岛链/环礁/侧向绕行，奶池使用块状掩体/盆地/开阔口袋。每风格16个独立编排骨架，各有8种空间方案，构成128个普通候选；特殊房不计入此数。

空间方案改变掩体数量、朝向、分组和危险区数量/位置；有些留出暴露射界，有些增加侧翼掩护。受控位置候选用于适配外壳及入口，不旋转整房或仅扩大外壳制造新布局。门口保留半径14净空，中央交互区和奖励间距独立保留；其他通路允许绕掩体，不再强制每间都是同一个空十字。

`scripts/room-catalog-plans.mjs`保存64个风格专属编排。作者工具有明确上限，每候选最多4096次方案尝试，每组最多25个位置及8个中央掩体退台替代位；额外掩体/机关只使用有限周边候选。合法摆放先保证完整模型、3单位边框、8单位可见间距及入口；实体障碍间及至墙体预留22单位通道余量，再按风格和空间方案选择危险区。障碍长边是短边整数倍，地刺宽高是16的整数倍。

内部计数**完全排除外壳**，忽略ID、风格、机关名称/朝向/时序，按平移和旋转/镜像归一化。每风格128种，全风格合计512种互异；另把坐标吸附到32单位粗网格后再次要求每风格128种，防止小幅位移凑数。作者工具与独立单测分别执行这些检查。几何唯一不保证好玩，负责人仍须看图并试玩。

运行时JSON保存共享外壳表和紧凑布局记录；模块加载只展开数据和冻结对象，不做布局搜索。完整展开的529项供审图使用，不进入运行包。每个预缓存文件超过2 MiB时构建直接失败，不能静默漏缓存。

## 一份墙块几何

轮廓支持轴对齐及45°线段，顶点落在8单位网格。离散成连续内部格后，外沿按完整8宽墙块连续铺设；45°段的相邻墙块沿斜线前进，素材不旋转、不变形。连续至少三块沿45°推进才认作斜墙。两块斜邻的直角需补闭合角：凸角在房外补格；凹角保留内侧连接格，不在另一侧向地面突出。判断基于未补角的原始墙序列，新增角块不反向影响判定。真正45°段及135°接点不补第二层。按y/x画完整墙块，保留既有遮挡。

墙块不是光滑三角形：可通行边界采用实际格子形成的阶梯，并扣除完整南墙的9.6单位投影。相同边界生成模拟多边形和Arcade不可通行填充矩形，导航、视线、弹体和身体不能各用一条近似线。门只放在横竖直段，四向入口沿法线向内24单位，避开机关与障碍。渲染/导航使用固定最大包围范围，碰撞体和纹理池复用。

当前作者工具输出按列连续的轮廓，编译器对不支持的断列/空洞明确报错，不擅自填平。这是可验证的几何能力边界，未来扩展轮廓族须同时扩展物理编译与全量验证。

## 安全与验证边界

生成器保留中央交互区；编译后的玩家、怪物、武器、出口与奖励锚点同时避开阻挡和陷阱。奖励额外检查左右奖励间距。RoomArena的动态安全查询也避开陷阱，不能在静态候选耗尽后落回危险区。

普通战斗房保持地形可通行比例及玩家中心相对空房至少80%；绝对面积与可达中心面积对比旧的空矩形（比对应旧家具房更严格）。连通测试包含未破桶、普通怪半径3–9及Boss半径14。固定小功能房按负责人授权允许缩小，但仍验证完整入口净空及交互可达。
