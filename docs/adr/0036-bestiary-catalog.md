# ADR 0036：怪物图鉴目录、稳定编号与静态展示帧

- 状态：待负责人合并批准。
- 提出者：Claude（#99）
- 关联：ADR 0023（可见图片与碰撞分离）、ADR 0030（怪物招式与图集）、ADR 0033（装饰预算）。
- 设计与布局：[主城怪物图鉴](../design/bestiary.md)。

## 背景

负责人要求主城加图鉴：左侧方形卡片网格（左上编号），右侧名字、攻击方式、简介，展示全部怪物。编号要稳定，不能因为数组重排或以后加怪而改变；#100 会重绘怪物，图鉴要沿用同一套映射接入新图。此前怪物名字的 i18n 键 `enemy.*` 在 data 里有引用，但文案文件里没有，因为以前从不显示怪物名字。

## 决定

1. **目录数据** `src/data/bestiary.ts`：`BESTIARY` 的类型是 `Record<EnemyId, BestiaryEntry>`，每种怪物都必须有一条，漏加会编译失败。名称、生命、速度等不重复存储，直接取 `ENEMIES`；条目只存图鉴特有的信息：
   - `no`：编号；
   - `role`：`common | minion | boss`；
   - `frame`：静态展示帧，填 `{ action, index }`，指向怪物资源注册表；
   - `attack`、`desc`：文案 key。
2. **编号规则**：编号是显式字段，与对象或数组顺序无关。一经分配不改；新增怪物取当前最大编号 + 1；删除怪物时编号保留，不复用。单测检查编号唯一、为正整数。
3. **派生目录** `src/sim/meta/bestiary.ts` 的 `bestiaryCards()`：按编号升序返回只读数组，首次调用时计算并缓存。出没楼层和产生者都由数据推导，不手写，避免和遭遇表不同步。每张卡片包含：
   - 编号与三位标签（`001`）；
   - 分类、名称 / 攻击方式 / 简介的文案 key；
   - 生命、平时移动速度（炮台、只会跳的、只会原地冲锋的记为 0）、接触伤害、是否免疫冰冻；
   - 出没楼层：遭遇表里的楼层；首领在 Boss 层；小怪取产生它的怪物所在楼层；
   - 产生者：`split` / `summon` 指向它的怪物；
   - 静态帧：图集纹理 key、文件名、帧左上角、宽高、朝向。
4. **静态帧**：通过 `enemyAnimation()`（现有资源注册表）解析，不复制图片，也不新建纹理。界面显示前裁掉帧内透明边距、统一朝右，再等比放大填满卡片。#100 重绘时只换图集文件和帧坐标；如果动作名或帧序号变了，就改 `BESTIARY` 里的 `frame`，单测会检查帧存在、且落在图集图片范围内。
5. **文案**：
   - `enemy.<id>` 存名称，`bestiary.<id>.attack` / `.desc` 存攻击方式与简介，`bestiary.*` 存界面标签，中英文同步提供。
   - 攻击方式与简介按实际 AI 编写，**不写阿拉伯数字**，具体数值由界面从 data 读取。
   - 单测里的「说明与实际 AI 一致」逐句断言文案对应的数据事实；怪物数据改动导致不一致时测试失败，提醒同步改文案。
6. **不设解锁**：图鉴默认展示全部条目，不读取存档或档案，也不新增存储键。

## 取舍

- 编号按首次出现的楼层排，便于玩家按进度翻看；以后楼层遭遇调整也不会重排编号，所以编号和楼层顺序可能逐渐对不上。这是稳定编号的代价，可以接受。
- 文案不写数字，牺牲了一点精确度（例如「几只蝌蚪崽」），换来调数值时文案不会过时。需要看准确数字时，界面显示 data 里的生命、速度和接触伤害。
- 透明边距在运行时裁切，不另存裁剪坐标：#100 重绘后不需要重新生成一份裁剪数据。代价是首次打开时多一次很小的离屏绘制。

## 验证

`tests/unit/sim/bestiary.test.ts`：条目覆盖全部怪物、编号唯一、schema、分类与遭遇表和分裂/召唤字段一致、静态帧在图集范围内、中英文文案齐全且不含数字、目录排序与推导的楼层和产生者、不走动的怪速度为 0、说明与实际 AI 逐句对照（普通怪与奶怪）。
