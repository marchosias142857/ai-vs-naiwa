## 几何、布局与确定性

全目录检查532模板、3,608个模板/半径组合，1单位网格；129种不同实体几何缓存复用（陷阱位置/朝向差异仍分别检验）。[原始面积记录](style-room-catalog/clearance.json) 保留每项ID、半径、面积和连通分量。

- 普通怪半径3–9，玩家6，Boss14；未破桶纳入阻挡。全部合法中心单连通，四向入口、出生、交互与奖励锚点安全。
- 战斗/Boss房最低地形可通行比例94.445%；玩家中心相对同轮廓空房最低88.334%。最低绝对地形面积67,812，玩家中心面积57,872；分别高于旧空矩形47,872与42,640。旧空矩形比旧家具房更严格，小型功能房按负责人许可不套此绝对下限。
- [布局密度记录](style-room-catalog/layout-metrics.json)：战斗房全部机关含边框的保守可见矩形占地为1.847%–5.020%，以对应空房采样面积为分母；这不是爆炸或敌人攻击范围覆盖率。各空间家族计数一并公开。
- 全部障碍长边为短边整数倍、地刺宽高为16整数倍；完整边框计入间距，组间至少8。桶距掩体额外保留18单位大怪通路和4单位导航余量，避免斜角窄缝。
- 轮廓支持轴对齐/45°且按列连续；全墙块绘制、模拟阶梯轮廓、Arcade填充来自同一份编译数据。完整墙顶和墙身都是阻挡，斜段不设门。
- 作者工具与独立单测均检查旋转/镜像/平移归一化后的结构唯一性。每风格128个战斗结构，不用特殊房或改名补数。
- 4/7/8/15/22房配置各50种子；四风格在1/2/4/10/99层分别30种子；同层无放回，同种子清单一致，root流不推进。随机风格分配接口独立测试，当前默认顺序策略没有伪装成已启用随机。

## 加载与内存边界

[资源对照](style-room-catalog/resources.json) 和 [ABBA启动/堆样本](style-room-catalog/memory.json) 均对照同依赖重新构建的main基线。新模板数据增加JS体积，地图图像字节不增长。JS堆在暂停并请求GC后约9.51–10.07MiB→10.32–11.11MiB；这是两次样本范围，不能当长期泄漏或性能结论。显示对象1,026→1,117，主要是边界固定槽4→96和删除一个文字对象。换房后对象与纹理池保持恒定。

最大房间包围范围扩大，两个常驻8倍密度画布的理论RGBA由41,648,128增至71,204,864字节（增加28.19MiB）。不含图集解码、GPU副本、引擎开销；JS堆指标不能覆盖这部分。本任务没有以降低像素密度修改已认可美术，也没有宣称内存无回归。真机需关注换房上传和内存；小尺寸运行图集仍是单独后续建议。

启动观测时另有E2E负载，约2.7–3.3秒仅作能完成加载的记录，不称提速。Performance资源传输计数在该环境返回0，故传输体积取构建文件统计。模板数据使主JS接近2MiB预缓存单文件上限，新增风格前应继续检查该预算。
