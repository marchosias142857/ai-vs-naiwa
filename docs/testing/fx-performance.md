# 装饰特效优化与验收（2026-10-25）

基线为 main `b525516`（#93–#95 已合并）。负责人确认已在自己的设备上验证该版本；本记录不把这一确认换算成未提供的 FPS、设备型号、系统版本或测试时长。当前进入 GPT 与 Claude 合作细化阶段，旧 demo 独立实现授权已结束。

## 本轮改动

- 火花从 Arc 改为共享 32×32 纹理的 Image，池仍为 100 个。Phaser 4.1.0 的 `shape/FillPathWebGL.js` 每次绘制一个 Arc 都会分配 vertices/colors 两个数组；Image 路径避开这两份临时几何数组。
- 活动槽位用预分配数组和交换删除。每个物理步只更新活动火花，空闲时不扫描 100 个槽位；死亡计时、角色反馈的循环保持不变。
- 场景共享分类生成预算：每渲染帧火花 48、冲击圈 16、闪电 16。超限省略，不积压到后续帧；屏外装饰使用包含半径和留量的范围判断，按实际相机原点和缩放计算视野，避免左上角原点被 Phaser worldView 的中心口径误剔除。原有活动上限仍为 100/16/16。
- 闪电折线在事件发生时计算一次，两条描边复用；暂停和屏外期间的寿命仍由原有 sim 时间推进。
- 预警、危险区域、弹体、光束、冰冻提示、Boss 死亡演出和碰撞/伤害不走装饰预算；没有修改 sim、存档格式、玩法数值、输入或渲染分辨率。
- 调试面板新增接受/限额省略/屏外省略计数，便于后续添加特效时观察预算是否频繁耗尽。

## 同负载渲染对照

对照用项目锁定的 Phaser 4.1.0、1920×1080 画布、4 倍相机、相同位置/尺寸/颜色的 100 个火花；Arc → Image → Arc → Image，每轮 120 个真实渲染帧。测试直接统计 renderer 的几何提交与 draw call，并导出绘制提交耗时。场景不推进游戏 sim，不以模拟耗时计算 FPS。

| 指标                    | Arc       | Image          |
| ----------------------- | --------- | -------------- |
| 每个火花三角形数        | 99        | 2              |
| 100 个火花每帧几何索引  | 29,700    | 600            |
| 每帧 draw call          | 1         | 1              |
| 上述 Arc 路径的临时数组 | 200 份/帧 | 不再进入该路径 |

几何索引减少约 98%。这不表示整个游戏的帧耗时减少 98%；draw call 在这个微型场景里原本已为 1。CPU 绘制提交时间受共享机器、软件渲染与采样开销影响，只作为附带数据，不设时长门槛、不外推 iPhone FPS。自动化对照测试见 `tests/e2e/fxRender.spec.ts`，原始结果见 [fx-render-comparison.json](fx-render-comparison.json)。

复现：安装项目依赖和 Playwright Chromium 后，执行 `npm run test:e2e -- tests/e2e/fxRender.spec.ts --project=desktop --project=mobile-landscape --workers=2 --retries=0`。测试报告附带 `fx-render-comparison` JSON；需要设备结论时在目标设备、相同负载下另测。

## 后续扩展约束
