## 行为与覆盖

右攻击轮盘按下即有攻击意图，不再等待 120 ms；任意可表示非零偏移立即提供手动方向，回到精确圆心仍按住攻击。左移动摇杆、硬件手柄死区和多指所有权不变。InputFrame 仍只传原始输入，sim 按攻击类型决定 20 款弹体自瞄、5 款激光/近战手动。

目标按射程内最近且视线可达选择，平手用实体 ID，跳过预警、死亡、地下/出土和中心重合目标。每攻击步重新选择，无锁定计时或新增存档状态；无目标沿用原方向。连射剩余子弹和蓄力释放步也选敌；弓仍松手发射，释放帧身体跟随出手方向。未更改武器数值、散布、能耗、攻击时序、弹体碰撞、AI、地图、随机调用和存档字段。

输入单测覆盖 `1e-10`、`0.001`、`0.25`、6、56 CSS px 的轴向/斜向偏移（用浮点实际表示的坐标差归一化），按下、拖动、回中、自定义大小、拖出、所有权、释放/取消、重置。新 sim 单测覆盖 25 款 × keyboard/touch/gamepad 的实际发射事件或近战/光束方向，以及目标过滤、遮挡、范围、连射、蓄力、切枪和 90 步保存恢复后的完整状态/随机流一致。

浏览器夹具只安排交战双方、测试障碍和物理步时钟，攻击从实际 DOM 或 Phaser GamepadPlugin 输入，经 InputScene → DemoSession → CombatBridge → sim → Arcade。断言输入方向、真实 `weapon:fired`、近战/光束状态、手枪 Arcade 速度及回旋镖速度。目标在下方，输入朝左；手枪散布仍按数据允许 ±2°，没有为了测试删掉散布。墙体遮挡走 RoomArena 同一份静态体和 LOS 几何。

## 过程中发现的问题

1. 初轮夹具的鼠标投影、相对房间中心的障碍坐标，以及把有散布手枪误当零散布的断言不正确；修正夹具与数据约束后实际输入矩阵通过，生产瞄准算法无需为这些问题改动。
2. 两项旧单测依赖“没有自瞄”：原角度用例改为验证自瞄中心及原散布；多弹体存档用例改为在冰沙阶段生成新的目标，避免前几种武器已自动打死旧目标。保留多弹体在飞、蓄力、冰冻和逐项恢复一致断言。
3. 删除 Boss 浏览器用例中的测试端选敌代码后，用 RT 和生产自瞄完成击杀、耗能切枪与结算。储存禁用用例初跑等待 HUD 的 5 秒内尚未完成场景加载，失败截图中提示已出现；补上场景就绪等待，仍保留未保存提示及实际移动断言。

最终检查曾遇到一次本地执行会话中断，未计为通过；随后完整重跑通过。格式/lint/类型/单测/构建的最终日志对应同一份运行代码，之后只补验证记录。

在功能分支本地预览打开 `?scene=Game&seed=42&god=1&weapon=fin_boomerang`，进入战斗后朝敌人的相反方向按住攻击，应仍向有效敌人出手；换 `lantern_beam` / `cutlass`，微小拖动应立即沿手动方向攻击。`coral_bow` 按住蓄力，松手才发射。清空房间后检查原方向回退、双指、切枪、取消和暂停恢复。

待负责人实机确认最近目标切换的手感。当前每步选最近目标，没有 0.25 秒保持期；两敌距离交叉可能换敌。Claude 需重点复审选敌、LOS/隐藏态、弹体分类、范围、蓄力/连射/切枪以及同版本恢复。保持 Draft，负责人验收后合并。
