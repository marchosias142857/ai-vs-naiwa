## Claude 需要定稿的时序 / 共享视图

1. `ActorView` 只有 pose/move/aim/lift，未暴露招式阶段进度。`EnemyArt` 在首次观察到 action 变化时自建 `PoseClock.since`，不能保证读档首帧与 sim 阶段一致，也无法辨别跳过渲染期间同名动作的新一轮。需要只读的阶段及进度/时长语义；字段名与 ADR 由 Claude 起草。
2. `EnemyBrain.time/span` 已随存档保存，但旧 `charge_dash` 在 `brain.ts` 只写 time，不写 span；不能直接统一用 `1-time/span`。常规射击另用 cooldown/shot，必须明确这两类的派生方式，不能假定所有动作都经过 `start/next`。
3. 普通射击的 windup 只是冷却末段的表现：冷却已经到期后恢复视线可立刻开火。若要求每次射击必有完整前摇，属于 AI/手感变化，须在方案里明确，不应由表现层延迟子弹。spin 目前无前摇，本项也不能暗中加延时。
4. `pose` 会把多种恢复阶段映射为 idle：lash、bump、hop 后半段等；rain 立即 finish。需要区分“已有阶段只读映射”和“新增阶段影响攻击间隔”。优先复用既有时间，不为了播完动画改 sim 结算。
5. 跳跃只暴露 lift/aim，没有目标坐标。不能用上一渲染帧速度外推落点；请明确由 sim 给出预计落点的方式及碰墙、击退时的更新规则。实际落点受物理位置同步约束，提示必须随真实规则调整。
6. 冰冻会跳过 AI 更新，pose 保留；`HazardLayer` 隐去技能提示，但 `CombatFeedback` 仍画 warning 圈。统一定义冻结时的动画暂停/提示状态；死亡、切房、槽位换 ID、读档首帧必须重置或从快照重建，无须等事件重放。
7. 普通地面怪在 windup 时仍有既存接触伤害；“前摇不提前造成该招伤害”不能误写成全身无敌或关闭所有接触。舌击、自爆、落石的独立生效边界应分别测试。

契约应只读、定长复用，不逐步构造临时对象；game 不读取或强转内部 EnemyBrain，不调用 save() 作为每帧查询接口，不用渲染回调触发伤害。已有 `enemy:acted` 可驱动一次性装饰，但不能作为读档后恢复必要攻击提示的唯一来源。必要新持久化字段同步存档校验与恢复，尽量从已有持久状态派生。

2. **方案与 sim 契约 PR（Claude）**：读取本表，定稿专属动作与锁定/进度/落点语义；起草新 ADR（当前最大编号 0037，提交前重新查重），实现必要派生视图及 sim/存档测试。保留现有规则与所有危险提示，等替代接入再删。

## 验证清单

- 固定物理步检查每种被替换招式的前摇末步、生效首步与恢复末步，方向锁定边界，以及 Boss 66% / 33% 阶段。对照相同输入与随机种子，确保无重复攻击或意外改变伤害时间。
- 同一 sim 快照在不同渲染间隔、首次绘制、暂停恢复、冻结解冻下选择相同关键帧；同名招式再次开始和跳过渲染不得沿用旧时钟。
- 保存 → JSON → 读档：在每个阶段、锁定前后、落石着地前后检查必要提示立即恢复；保留同输入 sim 状态一致性测试。
- 死亡/中断/切房、Boss→蝌蚪等槽位复用无残留；已生成的区域和落石按现有独立生命周期处理。
- 装饰预算为零、池满及密集战斗时必要提示仍可见；对象和纹理计数稳定，无逐帧创建/销毁。
