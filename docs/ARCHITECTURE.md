# 架构

核心规则：**sim 决定发生什么，game 决定看起来怎样。** 本文描述当前合作细化基线；demo 历史评审索引见 [demo-overview.md](demo-overview.md)。

## 1. 分层与依赖

- `data/` 只定义玩法常量和 schema，不依赖其他层。
- `sim/` 只依赖 data，不导入 Phaser、game、services 或 debug。
- `game/` 依赖 sim、data、services，负责 Phaser 物理、绘制与 DOM UI。
- `services/` 只依赖浏览器 API，负责存储、设置、音频和页面生命周期。
- ESLint 与 architecture 单测同时检查边界；zod 只在测试/校验中运行，不进入生产包。

## 2. 一局的模块与生命周期

| 模块                             | 职责                                                              |
| -------------------------------- | ----------------------------------------------------------------- |
| `MenuScene` / `MenuPanel`        | 回到主城（保留冒险存档）、现场续玩/入口兜底、战绩与设置           |
| `HubScene` / `HubPanel`          | 不持武器的主城；地牢门确认新冒险，祭台天赋与常驻怪物图鉴          |
| `GameScene` / `DemoSession`      | 组装本局 sim、地图、输入、池、反馈、HUD；升级与胜负状态接线       |
| `DungeonRun` / `generateDungeon` | 确定性拓扑、有限波次、房间锁门、清房、层间推进、胜负              |
| `RoomDirector`                   | bridge 之后消费刷怪命令，按楼层派生随机流；实体池满时待有空位再刷 |
| `CombatWorld`                    | 角色状态、AI、弹道、近战扇形命中、伤害、资源、技能、玩家朝向      |
| `CombatBridge` / `RoomArena`     | 输入边沿锁存、物理同步、碰撞反馈、墙体复用、门口切房、地图查询    |
| `NavigationGrid`                 | 固定四邻网格，每个半径缓存 blocked 与流场，目标格由坐标计算       |
| `LootSystem` / `DemoObjects`     | 固定楼层槽位、自动物资拾取、显式原槽换枪；只展示当前房间的武器    |
| `CombatFeedback` / `CombatAudio` | 事实事件到预热反馈/音频；死亡表现结束才回收角色                   |
| `DemoHud` / `InputScene`         | 功能 HUD、地图、选择/结算；渲染帧输入和触屏操作                   |
| `RunPersistence`                 | 完整现场同步保存及入口兜底，胜负清档并记录一次战绩                |

关闭场景时清理 WORLD_STEP、PRE_UPDATE、EventBus 订阅、DOM/手柄菜单、碰撞器与各池。重来新建 CombatWorld；InputScene 实例可复用，但 create 重置布局缓存。原 M1 入口保留在 `?scene=Game&room=arena`。

## 3. 时间、输入与物理（ADR 0004）

每个渲染帧只 sample 一次。InputScene 按其输入插件时序采样，战斗 PRE_UPDATE 取得缓存帧交给 bridge。物理后的 GameScene.update 发布玩家当前位置作为下一帧瞄准原点。

角色坐标、Arcade 碰撞圆与瞄准原点均为身体中心（ADR 0023）。触屏轮盘每次按下先保持 `fire=false`，拖出死区立即定向首发，留在死区达到 `INPUT_UI.aimWheel.firstShotDelayMs`（初值 120 ms）才朝当前面向首发；鼠标与手柄不经过该等待。sim 仍按「瞄准 > 移动 > 保持」决定朝向。

Arcade 完成本物理步移动与 overlap 后，WORLD_STEP 依注册顺序执行：

1. bridge：子弹寿命 → 同步 body.center → sim.step(dt, input) → 清边沿 → 应用速度/阶段 → 消费 spawns。
2. CombatFeedback：表现计时，死亡结束后 finishDeath。
3. DemoSession：导演 → 拾取 → 走门/出口 → 升级/结算计时。

0 个物理步的渲染帧保留边沿，多个物理步只给第一步。DOM 动作使用 pointerdown + preventDefault，仍经过渲染采样和 bridge 锁存。技能/切枪/交互按钮跟随 touchVisible，暂停或物理暂停时禁用。ActorView/BulletSpawn/StepResult 均为只读复用视图，消费者不跨帧保存。

## 4. 规则、弹道与事件

弹幕武器和敌方攻击共享 `FirePattern(ctx, sink)`：往预热 BulletSpawn 输出池写入，不返回新数组；开火上下文、弹丸记录、事件 payload 复用。规则给期望速度，Arcade 决定位置。碰撞调用 hitActor/hitWall/contact，寿命结束调用 releaseBullet。

近战在 sim 的 WORLD_STEP 内按数据中的范围、扇形、挥动时长、冷却与墙体视线判定，同次挥动每个目标只受击一次，不使用子弹池（ADR 0022）。sim 枪口使用角色固定标准持握点与武器偏移；逐帧持握点只驱动画面，左向镜像和朝上背后遮挡不参与战斗结果（ADR 0021、0023）。

| 事件                                  | 发送方      | 订阅方                               |
| ------------------------------------- | ----------- | ------------------------------------ |
| `entity:spawned` / `entity:activated` | CombatWorld | 实体表现/预警                        |
| `entity:damaged` / `entity:died`      | CombatWorld | 反馈、音效、掉落、DungeonRun 统计    |
| `weapon:fired` / `bullet:hit`         | CombatWorld | 闪光、命中反馈、音效                 |
| `weapon:swung` / `melee:hit`          | CombatWorld | 近战弧光、命中反馈、音效             |
| `room:entered` / `room:cleared`       | DungeonRun  | 场景、清房奖励、音效                 |
| `run:ended`                           | DungeonRun  | 结束通知；GameScene 读取状态显示结算 |

单次子弹命中依次 damaged →（致命时）died → bullet:hit，critical 一致。EventBus 订阅写时复制，emit 遍历开始时的数组快照。

## 5. 固定容量与随机

预热 500 子弹、31 规则角色/物理角色、100 瞬时反馈、64 掉落槽/表现、16 内墙和 8 音频声部。预警使用固定图形，不依赖易满的瞬时反馈池。同步事件内回收的角色记录等外层调用结束再复用，防止同次命中串号。

武器掉落记录房间编号，换房保留、换层清空；普通物资换房清空。普通掉落不能占用武器预留槽。拾取第二把武器时，旧第二把直接放回原地面槽并移到脚下，满池也无需新增槽；手枪不掉。

所有随机走 Random。地图 `map:${floor}`、布局 `layout:${floor}:${room}`、升级 `upgrades:${floor}`、掉落 `loot:${floor}`、刷怪 `encounters:${floor}` 独立 fork；刷怪再拆种类/位置。后面三条流每层重置；AI `ai`、特殊弹体 `shot` 各自独立 fork 并进存档。完整存档保存各随机流（包括局级散布/暴击），在相同物理步输入下与不中断运行做精确一致性对照；入口兜底不承诺还原退出时战况。

## 6. 存储与浏览器生命周期

| 当前存储                | 内容/时机                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `avn.run.v2`            | sim、物理槽位/空闲栈、子弹、死亡计时、挥动与入口副本；开局/换层、暂停、退出、pagehide/hidden 同步保存 |
| `avn.floor.v1`          | 只为读取旧版入口检查点保留；成功写入 v2 后移除，死亡/胜利同时清除                                     |
| `avn.profile.v2`        | 战绩、累计天赋点、天赋等级与最近 16 个结算 ID；购买和结算成功写盘后生效                               |
| `avn.profile.v2.backup` | 最近一次修复或重建前的档案原文；备份失败不得覆盖原档                                                  |
| `avn.profile.v1`        | 仅供迁移历史战绩和补发有上限的点数，保留原键不再写入                                                  |
| `avn.settings.v1`       | 语言、音效、受击闪光；修改即写                                                                        |
| `avn.ui-layout.v1`      | 血/甲/能量、双摇杆及动作按钮的位置、大小、透明度；编辑器确认保存                                      |

当前使用带版本的 localStorage，失败/损坏不会阻止新局。完整恢复通过 sim 轻量解析及 game 逐字段校验；data 中共享字段规则与 zod 成对测试。版本/数据变化或现场损坏时独立校验入口副本，并显示不同提示；JSON 损坏不可继续。同步写入失败保留旧档，终局不能兜底复活。实现遵循已批准的 ADR 0019，近战状态遵循 ADR 0022；特殊弹体、区域与石块按原槽位恢复（ADR 0030–0031），机关状态及近战机关命中掩码遵循 ADR 0032。

手动、生命周期、升级、终局、恢复、主城交互分别持有暂停原因；解除一种原因不会越过其他原因。战斗现场恢复先冻结 sim 和物理倒计时 3 秒，期间再次暂停或切后台后重新计时；非战斗现场直接恢复。暂停、保存、恢复时清理输入与 bridge 边沿，持续按住的手柄须先回中。pagehide/hidden 在事件回调内同步保存，不能仅凭暂停或写入尝试就报告保存成功。

天赋与奖励的纯规则在 `sim/meta/`，`game/save/metaProfile.ts` 负责迁移、购买和结算事务；`services/profile.ts` 只负责原文读取、备份与写盘，不依赖 sim。`FloorCheckpoint` v2 保存 runId 和开局天赋，完整恢复不再次施加；入口兜底按冻结配置重放。启动时丢弃已结算 ID 的遗留冒险。成功结算先保存档案再删除冒险；失败时终局仍清理，内存奖励回主城（或直接重开）只重试一次，仍失败则提示未保存并放弃。关闭页面会丢失尚未写盘的奖励，重复生命周期回调不会触发补发。

`TalentPanel` 创建固定的 12 个节点、前置连线和详情区，购买/选择时刷新；不会在战斗帧循环创建 DOM。交互独立持有暂停原因，关闭时清空按键边沿。触屏、键盘 Tab/Esc 和手柄导航均走现有输入/生命周期规则。祭台为独立版本 PNG，随 Workbox 预缓存。

`BestiaryPanel` 只消费 ADR 0036 的 `bestiaryCards()`，首次打开构建目录卡片，后续开关复用；退出主城时通过同一 AbortController 清理监听与 DOM。静态图片使用已加载图集，首次按 ID 扫描透明边距，只缓存裁剪坐标，CSS 背景定位与翻转，不创建 Phaser 纹理或持有额外位图。图鉴使用 interaction 暂停，关闭清空主城输入；四向键/左摇杆选择，PageUp/PageDown 或右摇杆滚动详情。切后台后手柄须回中；目录不读写冒险或档案。

音频仅在真实手势首次解锁，游戏内场景/物理暂停只归零声部增益并阻止新包络；后台或离开战斗场景才 suspend。后台恢复被浏览器拒绝时等下一次真实手势重试。PWA 使用 Workbox，更新由用户明确刷新，不自动打断战斗。

## 7. 参数、预算与验收

逻辑世界保持 480×270、16 px 瓦片，渲染倍率 `RENDER_SCALE = 4`，基准画布 1920×1080。主城/地牢按安全区横屏宽高比扩展画布，保留至少 6 倍的原有倍率；世界视口铺满画布，HUD 和操作控件覆盖其上（ADR 0024、0029）。镜头每渲染帧直接以人物为中心，不受房间边界限制；滚动对齐最终渲染像素，居中误差不超过半个渲染像素。房间外使用相机纯黑清屏色，不再平铺墙砖背景（ADR 0034 替代旧的边界限制和背景规则）。图集使用 NEAREST 采样，画布和文字不套用整屏低分辨率像素化。

资源按角色注册表及怪物/武器/房间图集加载，含独立角色反应动画、面部帧、门框和标题插画；所有运行时资源进入 PWA 缓存，不再只有五张 PNG。角色、武器与特效视图预热复用，持握点、镜像和动作时长遵循数据配置。

装饰特效由 `FxBudget` 按渲染帧分类限额：火花 48、冲击圈 16、闪电 16 次生成请求。屏外装饰省略，超限不排队；已有池仍保持 100/16/16 的活动上限。火花共用一张 32×32 运行时纹理，更新只遍历活动槽；闪电折线在生成时计算一次。危险区域/预警、弹体、光束、冰冻提示和 Boss 死亡演出不受该预算削减，物理与伤害完全由 sim 按原锁步处理。详见 ADR 0033 与 [验证记录](testing/fx-performance.md)。

当前由 GPT 与 Claude 合作细化，负责人已确认自己的设备验证（2026-10-25）；历史独立 demo 授权已结束。

性能目标：中端安卓平均 ≥55 fps、最低 ≥45 fps；战斗 draw call ≤30、内存 ≤300 MB、包体 ≤8 MB（不含音乐）。这些仍是量化目标；负责人已确认设备验证，但未提供这些指标的实测值。后续性能回归使用带柱子房间与混合怪、相同负载的帧时/draw call 报告；不能将无 GPU 软件渲染或模拟推进速度当作手机 FPS。

验证用 Vitest（数据、边界、随机、规则、导航、池）、Playwright（真实 Arcade、菜单/输入/存储/生命周期、离线和连续更新）及负责人真机试玩。当前记录见 [demo 交付验收](testing/demo-production-acceptance.md)，旧灰盒记录保留作历史基线。
